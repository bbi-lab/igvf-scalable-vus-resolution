# Figure Assembly (manual, Adobe Illustrator)

After Stage 3 ([Figure preparation](../README.md#3-figure-preparation))
generates every repo-native figure asset under `data/output/figures/assets/`,
the project team assembles and exports the final submission-ready figures by
hand in Adobe Illustrator. This step is only needed when preparing a paper
submission, not for a normal pipeline run, and is the only step in this repo
that needs neither Docker nor Poetry -- just a local Illustrator install.

## What's checked in

- `data/output/figures/illustrator/figures_2-6.ai` and
  `extended_data_figures.ai` -- the two Illustrator documents that assemble
  every figure this repo generates assets for, by placing the panel files
  under `data/output/figures/assets/` (and, for `extended_data_figures.ai`,
  the three externally-sourced Extended Data Figures below) onto per-figure
  artboards.
- `data/output/figures/illustrator/export_artboards.jsx` -- exports every
  artboard of the active document to its own file; see
  [Exporting](#exporting) below.
- `data/output/figures/illustrator/relink_extended_data_figures.jsx` -- a
  utility used when Extended Data Figure numbering changes, to relink
  `extended_data_figures.ai`'s assets and rename its artboards to match. Not
  needed for a routine export; kept for the next time a renumbering happens.
  See its own header comment for the mechanics.
- `data/input/external_figure_assets/` -- Figure 1, Figure 7, and Extended
  Data Figures 1, 11, and 12, which this repo doesn't generate at all; see
  [Externally-sourced figures](#externally-sourced-figures-figures-1-7-and-extended-data-figures-1-11-12)
  below.

## Updating links before exporting

Illustrator has no relative-link mechanism, so every placed PDF/linked PNG
in both `.ai` files records an absolute path from whatever machine prepared
the submission (e.g. `/Users/.../data/output/figures/assets/extended_data_figure_3/...`).
Before exporting from a different checkout:

1. Open both `.ai` files in Illustrator.
2. Open the Links panel (Window > Links) and check every link resolves;
   relink any shown as missing to this checkout's own
   `data/output/figures/assets/...` (and `data/input/external_figure_assets/...`
   for the three externally-sourced Extended Data Figures placed into
   `extended_data_figures.ai`).
3. If the Extended Data Figure asset folders have just been renumbered,
   `relink_extended_data_figures.jsx` can do this relinking -- and rename the
   matching artboards -- for you instead of relinking by hand. See its header
   comment for exactly what it does and does not handle.

## Exporting

With a document open and its links resolved, run `export_artboards.jsx`
(File > Scripts > Other Script...). It prompts for:

- **Format** -- PNG or PDF, exported one file per artboard, named after the
  artboard with no document-name prefix.
  - **PNG** -- 300ppi, transparent background, clipped to the artboard.
    Suitable for embedding directly into the paper's main-text figures.
  - **PDF** -- suitable for submitting Extended Data Figures and
    Supplementary Figures.
- **PDF standard** (only when PDF is chosen):
  - *Standard (Acrobat 5)* -- plain PDF 1.4 export.
  - *PDF/X-3:2002* / *PDF/X-3:2003* -- **recommended, and the script's
    default**. Illustrator's own interactive Save As PDF dialog enforces the
    same standard for the same reason: a plain PDF export can leave some
    placed PDFs invisible, which PDF/X-3 avoids (it also forces Acrobat
    4/PDF 1.3 compatibility, matching that manual dialog). 2003, the default,
    preserves live transparency; fall back to 2002, which flattens
    transparency instead, if a given export still looks wrong.

Select or create `data/output/figures/assembled/` as the destination when
prompted -- both `.ai` files should export there.

## What gets exported

- Both `.ai` files assemble some alternate panel/figure versions that aren't
  used in the final paper (the `alt`/`missense`-suffixed variants documented
  per-figure in [`docs/figures.md`](figures.md)) -- these still live on their
  own artboards and get exported like everything else. Leave their output
  files out of the submission package.
- Each Extended Data Figure has two artboards -- one with its caption baked
  in, one without -- and both get exported as separate files. Pick whichever
  a given submission portal wants (e.g. the journal's own figure vs. a
  caption-free version for a separate captions file).

## Externally-sourced figures (Figures 1, 7, and Extended Data Figures 1, 11, 12)

None of these five are generated by this repo's pipeline -- they're checked
into `data/input/external_figure_assets/` as provided externally, but the
two groups are handled differently:

- **Figure 1 and Figure 7** are each their own standalone Illustrator
  document (`figure_1.ai`, `figure_7.ai`) -- neither is placed into
  `figures_2-6.ai` or `extended_data_figures.ai`. Open each one directly
  and export it the same way as the two main documents above, with
  `export_artboards.jsx` (PNG and PDF), into
  `data/output/figures/assembled/`.
- **Extended Data Figures 1, 11, and 12** have no `.ai` of their own in this
  repo -- only a finished PDF (plus an SVG for 11/12, kept for reference).
  Their PDFs are placed directly into `extended_data_figures.ai` as linked
  assets (see [Updating links before exporting](#updating-links-before-exporting)
  above), so they're already part of that document's own artboards and come
  out automatically when it's exported -- there's no separate export step
  for them.
